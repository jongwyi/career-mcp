# 인턴 공고 매칭

프로필과 공고 요건을 대조해 **지원할 만한 곳**과 **지원서에 쓸 재료**를 찾는다.

`$ARGUMENTS` 가 있으면 키워드나 지역으로 해석해 좁힌다. (예: `/search_intern 서울`)

**설계 원칙: 필요한 것만 가져온다.** 요건 전문과 근거는 기본 응답에 없다.
평가할 공고를 고른 뒤에 그것만 가져온다.

## 순서

### 1. 프로필 확인
`profile_read` 를 호출한다.

`missing_attributes` 에 항목이 있으면 **먼저 물어본다.** 대부분의 공고가
연령(만 15~34세)·학력·재학 여부를 자격 조건으로 걸기 때문에,
이 값이 없으면 지원 가능 여부 자체를 판단할 수 없다.
답을 받으면 `profile_set` 으로 저장한다.

### 2. 후보 조회
`jobs_match` 를 호출한다. (기본 8건)

응답이 두 갈래로 나뉜다.

- **`cached`** — 지난 평가가 그대로 유효하다. **다시 평가하지 마라.**
  공고 내용도 프로필도 그때와 같다. 점수를 그대로 쓴다.
- **`fresh`** — 아직 평가하지 않았거나 내용이 바뀌었다. 3단계로 간다.

`candidate_count` 가 0 이면 `ingest_status` 로 수집 상태를 먼저 확인한다.

### 3. 요건 가져오기 — 골라서
`fresh` 의 제목·기관·직무분야·학력을 보고 **평가할 가치가 있는 것만 고른다.**
명백히 맞지 않는 것은 여기서 걸러라 — 요건은 공고당 200~800자다.

고른 것만 `job_requirements(job_ids=[...])` 로 가져온다.

### 4. 평가
요건을 프로필 `evidence_facts` 와 대조한다.

- **적합도 점수** (0~100)
- **충족 근거** — 어떤 요건을 어떤 경험으로 충족하는지. `fact_id` 를 반드시 포함
- **부족한 요건** — severity(low/medium/high)와 구체적 보완 제안

**`unverified` 표시가 있는 사실은 확정적으로 쓰지 마라.**
임포트된 사실에는 과장이 섞인다 — "기획을 논의했다"가 "기획에 참여했다"로
기록되는 식이다. 근거로 쓰기 전에 사용자에게 확인하고 `profile_confirm` 으로 표시한다.

`previous_score` 와 크게 다르면 이유를 설명한다.

### 5. 저장
**`match_save` 를 반드시 호출한다.**
각 항목에 `job_requirements` 응답의 `content_hash` 를 `job_hash` 로 넣는다.

이게 있어야 다음 실행에서 해당 공고가 `cached` 로 분류돼 재평가를 건너뛴다.
넣지 않으면 매번 처음부터 다시 평가하게 된다.

### 6. 지원서 재료 (사용자가 원할 때)
특정 공고에 지원하기로 했다면 `profile_evidence(fact_ids)` 로
인용한 사실들의 구체적 근거를 가져와, 자소서에 쓸 문장의 재료로 정리한다.

## 제시 형식

```
📊 후보 8건 (신규 2 · 기존 6) · 제한 공고 24건 제외

━━ 신규 평가 ━━
1. [27] 해양수산과학기술진흥원 — 82점
   D-3 · 서울 · 11명
   ✓ 충족: 사업기획 경험 (#49, #51)
   △ 부족: 관련 분야 인턴 경험 (medium)

━━ 기존 평가 ━━
[4] 한국산업안전보건공단 65점 · D-9
[19] 한국등산·트레킹지원센터 58점 · D-4
```

마지막에 다음 행동을 제안한다 —
`job_mark(status='saved' | 'applied' | 'not_interested')`.
`not_interested` 로 표시하면 다음부터 후보에서 빠진다.

## 주의

- **점수만 주지 마라.** 사용자가 원하는 건 "왜 맞는지"와 "지원서에 뭘 쓸지"다
- 근거 없는 충족 주장을 만들지 마라. 프로필에 없으면 gap 이다
- 공공기관 공고는 `preferred` 가 대부분 법정 가점(보훈·장애)이라 변별력이 없다
- 마감 임박(D-3 이하)은 눈에 띄게 표시한다
