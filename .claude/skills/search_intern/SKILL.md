# 인턴 공고 매칭

프로필과 공고 요건을 대조해 **지원할 만한 곳**과 **지원서에 쓸 재료**를 찾는다.

`$ARGUMENTS` 가 있으면 키워드나 지역으로 해석해 좁힌다. (예: `/search_intern 서울`, `/search_intern 정보통신`)

## 순서

### 1. 프로필 확인
`profile_read` 를 호출한다.

`missing_attributes` 에 항목이 있으면 **먼저 물어본다.** 대부분의 공고가
연령(만 15~34세)·학력·재학 여부를 자격 조건으로 걸기 때문에,
이 값이 없으면 지원 가능 여부 자체를 판단할 수 없다.
답을 받으면 `profile_set` 으로 저장한다.

### 2. 후보 조회
`jobs_match` 를 호출한다. `$ARGUMENTS` 를 keyword 나 location 으로 넘긴다.

응답에서 확인할 것:
- `candidate_count` 가 0 이면 `ingest_status` 로 수집 상태를 먼저 확인한다
- `excluded_restricted` 가 있으면 사용자에게 알린다 (장애인 전형·보훈 제한경쟁 등)
- `previous_score` 가 있는 후보는 지난번 평가 결과다

### 3. 평가
각 후보의 `requirements` 를 프로필 `facts` 와 대조한다.

**상위 5개는 깊게, 나머지는 한 줄로.**

깊게 볼 5개에 대해:
- **적합도 점수** (0~100)
- **충족 근거** — 어떤 요건을 어떤 경험으로 충족하는지. `fact_id` 를 반드시 포함한다
- **부족한 요건** — severity(low/medium/high)와 구체적 보완 제안
- **지원서에 쓸 재료** — 이 공고에 지원한다면 어떤 경험을 어떤 각도로 쓸지

`previous_score` 와 크게 다르면 이유를 설명한다.

`requirements_truncated` 가 큰 공고(요건이 잘린 공고)는
상위 후보라면 `job_detail` 로 전문을 가져와 다시 본다.

### 4. 저장
**`match_save` 를 반드시 호출한다.** 평가한 전체 후보의 점수를 넘긴다.

저장하지 않으면 다음에 같은 공고를 볼 때 비교 기준이 없어,
점수가 매번 달라지는 것을 사용자가 알아챌 수 없다.

### 5. 제시

```
📊 후보 24건 · 제한 공고 12건 제외 · 관심없음 3건 제외

━━ 상위 추천 ━━
1. [27] 해양수산과학기술진흥원 — 82점 (지난번 78점 ↑)
   D-3 · 서울 · 11명
   ✓ 충족: 사업기획 경험 (#49, #51)
   △ 부족: 관련 분야 인턴 경험 (medium)
   💡 지원서 각도: 창업 프로그램에서 문제를 재정의한 경험을
      R&D 기획의 "과제 발굴" 역량으로 연결

━━ 나머지 ━━
[4] 한국산업안전보건공단 65점 · D-9 · 전국
...
```

마지막에 다음 행동을 제안한다 —
관심 있는 공고는 `job_mark(status='saved')`,
지원했으면 `job_mark(status='applied')`,
아니면 `job_mark(status='not_interested')` 로 다음부터 빼기.

## 주의

- **점수만 주지 마라.** 사용자가 원하는 건 "왜 맞는지"와 "지원서에 뭘 쓸지"다
- 근거 없는 충족 주장을 만들지 마라. 프로필에 없으면 gap 이다
- 공공기관 공고는 `preferred` 가 대부분 법정 가점(보훈·장애)이라 변별력이 없다.
  우대사항으로 점수를 올리지 마라
- 마감이 임박한 것(D-3 이하)은 눈에 띄게 표시한다
